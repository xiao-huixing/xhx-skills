# Java Web API 与 Controller 代码规范

## 1. Query、VO 与复用

- 普通业务入参定义为有业务语义的 XxxQuery，业务数据出参定义为 XxxVO，使用项目已有 Result 包装并声明准确泛型。
- Query、VO 不强制追加 Create、Update、List、Detail 等操作词。字段语义、校验与暴露范围兼容时可以复用；确有不同职责或安全边界再拆模型。
- 新增、修改可以共用 Query，但 Service 方法分别表达创建与修改语义，不能因共用对象而统一为不明确的 saveOrUpdate。
- 不用数据库 Entity、持久化 PO 或无类型对象作为普通接口模型；不为复用构造包含大量无关可空字段的万能 Query。
- 复用 VO 不得额外返回无权查看或当前调用方不需要的字段；映射时明确数据裁剪。
- 无业务参数不创建空 Query；无业务数据可使用项目约定的 Result<Void>，避免只有形式价值的空 VO。
- 元数据驱动的动态表单可以在明确模型中承载受约束的 Map / JSON 字段。字段类型、可读写范围、数量和大小由服务端元数据限定；存量动态协议按原 JSON 契约演进。
- 文件、Servlet、流等属于协议参数；下载、SSE、签名原文等特殊协议遵循既有契约，不强行改变其输入输出形状。

## 2. 响应与协议

- 复用已有 Result、分页结构和错误码；禁止在模块内新增同义包装。
- 普通返回使用 Result<XxxVO> 或 Result<List<XxxVO>>；分页可沿用公共结果已有的 total 等字段，不另造相同结构。
- Java 模型重构必须保持已发布 JSON 形状、字段类型、空值/省略语义、时间格式和 ID 序列化方式。
- 成功提示与实际结果一致：已受理、已入队、已完成分别表达，Boolean 语义必须清楚。
- 业务失败不通过含义不明的 Result.success(false) 隐藏；自然的否定查询结果按其明确契约表达。
- 新项目路由优先表达资源和动作语义；已有项目按明确路由约定及公开契约编写，不机械改写既有 HTTP Method。

## 3. Controller 的具体做法

- 显式声明 RequestBody、RequestParam、PathVariable 或 multipart 绑定，业务参数优先封装为 Query。
- 使用 Jakarta Validation 或已有校验能力检查结构，避免同一请求混用正文和无注解散落参数。
- 登录用户、租户、管理员身份从可信上下文取得，不由 Query 决定。
- 调用清楚的业务用例，再包装响应；纯数据 VO 可以由 Service 组装，也可以在入口做简单转换。
- 业务状态、资源权限和复杂流程由业务能力负责；Controller 不直接调用 Mapper，不声明业务事务，不捕获所有异常自行拼接响应。
- 类和每个显式声明的方法都写中文功能 Javadoc，说明接口功能、参数含义、结果和必要的业务限制。

## 4. 校验规则

- 同一 Query 的校验规则一致时直接复用；规则有差异且共享模型仍合理时使用明确的 Validation Group，不强制每个 Query 都分组。
- 字符串检查空白、长度和规范化；集合检查非空、上限和元素有效性，嵌套对象按需递归校验。
- 参数规范化创建新值或新对象，不原地修改调用方 Query。
- 请求体、文件、动态字段和批量条数有明确上限。
- Controller 的结构校验不替代 Service 的业务不变量；多个入口共用权威业务规则。

## 5. CRUD 与业务动作

| 场景 | 代码要求 |
|---|---|
| 新增 | 明确只创建资源；ID 和审计信息由服务端产生；唯一性由数据库兜底 |
| 修改 | 明确目标存在、可修改字段和并发覆盖语义；区分不修改与清空 |
| 删除 | 明确软删、物理删除、隐藏或取消；处理关联限制与重复删除语义 |
| 批量 | 限定范围、去重和数量；逐项校验权限；明确整体或部分成功语义 |
| 查询 | 限制可见范围和数据量；明确空结果与不存在的含义 |
| 状态动作 | 使用清楚的业务动作名；检查前置状态并执行条件更新 |
| 预览后执行 | 说明预览是否产生副作用；执行时按实际需要复核权限、状态和预览事实 |
| 异步受理 | 返回与受理阶段一致的结果；需要跟踪时使用稳定业务标识 |

每项要求按实际场景使用，不强制为每个动作增加模型、策略、事务类或幂等记录表。

## 6. 分页与集合结果

- 明确分页参数来源、默认值、最大条数与稳定排序；具体值由项目或业务选择。
- 参数缺失或非法不能静默退化为无界查询；排序字段使用服务端白名单。
- Entity 转 VO 后保留 total、游标等分页元数据；空页不等于总数为零。
- 全量列表仅用于数量可控的场景；选项列表只返回必要字段。

## 7. 日志与错误

- 复用统一异常处理和接口日志组件，Controller 不复制日志与异常模板。
- 日志记录脱敏后的请求/响应摘要、耗时、真实业务结果和 traceId；正文按需记录，敏感或超大内容只记元数据。
- 错误提示、状态与错误码遵循 `04-exception-and-logging.md`，不改变既有协议约定。
