# Java 代码规范核对表

## 注释与可读性

- [ ] 所有显式声明的类、接口、枚举、record 和嵌套类型具有功能说明。
- [ ] 所有显式声明的方法和构造器均有功能 Javadoc，含私有、重写及访问器方法。
- [ ] 注释说清从功能角度做什么、产生什么结果及必要约束，不是重复名字或空标签。
- [ ] 复杂流程每一步的对应代码前都有功能注释，方法头总说明未代替步骤注释。
- [ ] 关键分支、循环、提前返回和失败处理的功能说明与实现一致。
- [ ] 集合和公共方法类型准确，未以原始类型或无依据的强制转换绕过约束。
- [ ] 空值与 Optional 契约明确，默认值计算及结果集合可修改性符合实际使用。
- [ ] Stream 表达清楚，中间操作未隐藏业务副作用，复杂流程未被压入链式表达。

## 职责与设计

- [ ] Controller、Service、DAO 各自承担正确职责，复杂入口保留流程骨架。
- [ ] 拆方法、拆类、接口和模块均有实际依据，没有机械转发层或假想扩展点。
- [ ] Query、VO 按业务语义合理复用，没有强制按 CRUD 建立重复模型。
- [ ] 对象映射不隐藏数据访问、外部调用或状态变化；不修改调用方或共享对象。
- [ ] 模块依赖单向、归属清楚，公共组件不反向依赖具体业务。
- [ ] 单例未保存请求临时状态，共享可变状态具有明确作用域和并发责任。

## 接口与业务行为

- [ ] 复用已有 Result 和分页结构，泛型准确，已发布 JSON 形状与字段含义保持一致。
- [ ] 结构校验、业务不变量与持久化约束边界清楚，身份和数据范围可信。
- [ ] 新增、修改、删除、状态变更、批量和异步结果的语义明确。
- [ ] 分页有界，转换和空页处理没有丢失总数或游标。

## 持久化与错误处理

- [ ] SQL 值参数化，动态标识符白名单化，查询和写入有正确范围。
- [ ] 事务保护需要共同成功的操作，状态与并发更新具有必要条件。
- [ ] 外部调用有超时与明确失败处理，防重、幂等和并发控制未混淆。
- [ ] 异常原因保留，用户提示安全，日志脱敏并记录真实业务结果。
