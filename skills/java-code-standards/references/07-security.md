# Java 安全编码规范

## 1. 输入与身份

- HTTP、RPC、消息、文件及历史数据中的外部输入均不直接视为可信。
- 当前用户、租户、管理员身份、价格和权限范围从可信上下文或权威业务数据取得。
- 认证、功能权限、资源归属和数据范围分别落实；批量操作不能以一个资源的权限代替全部资源。
- 权限条件由服务端生成，不接受客户端覆盖 dataScope 等内部字段；使用已有切面或拦截器时遵守其实际参数约定。
- 调整模型继承、方法参数或查询方式时，保留原有可信身份与数据范围传递，不因形式重构移除安全边界。

## 2. 注入与输出

- SQL 值参数化；表名、列名、排序和动态操作由服务端白名单或元数据映射决定。
- 动态表单限制字段、类型、数量和大小，禁止借动态字段修改系统身份、审计或权限条件。
- HTML 输出进行上下文相关转义，富文本按允许范围清洗。
- 系统命令使用参数数组和明确允许的参数，不拼接不可信命令文本。
- 模板、表达式、脚本和 JSON 多态类型限制允许能力；不反序列化不可信原生 Java 对象或任意类型。
- 错误响应不暴露 SQL、堆栈、路径、服务器地址、原始报文和内部配置。

## 3. 文件与外部地址

- 上传限制大小、数量、类型和实际内容特征；存储文件名由服务端生成，原始名称经过净化。
- 文件路径规范化并限定允许根目录；下载校验资源权限。
- 用户可影响的外部地址限制协议、域名、端口和重定向；解析和重定向后仍限定目标，防止访问未授权的本地或内网资源。
- 保持 TLS 校验；秘密不放入 URL、硬编码或普通日志。

## 4. 敏感数据与 Web 边界

- 密钥与凭证通过项目受控配置取得；密码使用适合密码存储的自适应哈希机制。
- 返回、导出与日志遵循最小必要原则，按 `04-exception-and-logging.md` 脱敏和截断。
- Cookie、CSRF、CORS 等根据项目认证方式配置；带凭据跨域不使用通配来源。
- 请求体、Header、集合、文件和分页设置资源上限；高成本入口沿用既有限流或防滥用能力。
- 安全规则所在类与每个方法必须有功能 Javadoc；复杂校验每一步代码前说明限制了什么业务风险及失败结果。
