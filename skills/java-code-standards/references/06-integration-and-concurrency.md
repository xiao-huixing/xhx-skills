# Java 外部调用、幂等与并发代码规范

## 1. 外部调用与适配

- 复用已有 Client / Feign / SPI。存在真实的协议或模型转换时使用适配器，不为每次调用额外建立转发层。
- 外部调用具有连接、读取或适用的总超时；失败转换保留原始 cause 和必要的依赖上下文。
- 服务端业务规则不依赖第三方原始报文、HTTP 响应或客户端实现细节。
- 降级只用于明确允许的业务行为，不把外部失败伪装成成功、空列表或正常无数据。
- 调用、适配、错误转换的方法和类都写功能注释；复杂流程每步对应代码前说明功能，执行 `01-core.md`。

## 2. 防重、幂等与并发控制

- 入口防重复提交、业务幂等和并发一致性分别解决不同问题，不用一个防重注解替代全部能力。
- 重复到达可能产生额外业务效果时，使用稳定业务键与明确作用域识别同一操作。
- 按真实需求使用唯一约束、预期状态或已保存结果实现幂等，不要求普通 CRUD 都新增幂等表。
- 需要结果重放时，先验证调用身份和操作作用域，再核对请求指纹；同键不同内容拒绝，已成功请求返回原业务结果。
- 处理中、成功、确定失败和可重试失败按业务需要区分，状态与业务写入保持一致。
- 并发修改优先使用数据库条件更新或约束；只有实际跨资源互斥需求才增加分布式锁。

## 3. 重试与消息

- 仅对瞬时、可恢复且操作幂等的失败自动重试；设置次数和总耗时边界，避免无限或紧密重试。
- 参数错误、权限拒绝、确定业务失败不重试。
- 消费者按可能重复、延迟和乱序处理消息，验证业务前置状态。
- 消息使用稳定业务标识、事件标识和必要上下文；重放不重复产生业务效果。
- 依赖事务提交事实的不可撤回通知不能提前发送；确有可靠交付需求时采用已有 Outbox、事务消息等能力。
- 异步接口准确表达已受理、已入队或已完成；需要跟踪时返回稳定操作标识。

## 4. 缓存与共享状态

- 缓存 Key 包含业务命名空间和必要租户维度；明确过期、数据来源和失效方式。
- 缓存不作为关键业务事实的唯一存储；业务修改与缓存处理的失败语义明确。
- 普通业务缓存不存原始秘密；认证组件确需维护会话凭据时沿用专用认证存储机制和访问边界。
- 不因使用 ThreadLocal 就假定异步上下文自动传播；线程或任务切换时显式传递必要身份与 trace 上下文。
- 优先消除共享可变状态；确有共享状态时明确所有权与同步方式。

## 5. 线程与锁

- 使用受管理且有界的执行资源，明确并发量、队列和拒绝处理，不按每次请求无限创建线程池。
- Virtual Threads 不取消下游连接数和并发边界；多个异步结果有明确超时、失败及取消语义。
- 锁具有租约或超时，仅持有者释放；不能只凭曾获得锁就认定后续写入安全。
- 跨步骤规则、失败释放和补偿代码必须有功能注释；不以注释代替实际释放与失败处理。
